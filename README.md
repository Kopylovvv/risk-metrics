## Локальная база данных

Требования: установленный и запущенный Docker с Docker Compose.

Все команды выполняются из корня репозитория.

### Первый запуск

Скопировать шаблон настроек:

```bash
cp .env.example .env
```

Заполнить в `.env` имя базы, пользователя и локальный пароль.
Файл `.env` исключён из Git.

Проверить конфигурацию и запустить PostgreSQL:

```bash
docker compose config --quiet
docker compose up -d --wait
docker compose ps
```

После запуска сервис `db` должен иметь статус `healthy`.

### Подключение

С компьютера база доступна по адресу `localhost:5433`.

Для подключения через клиент внутри контейнера:

```bash
docker compose exec db psql -h 127.0.0.1 -U risk_metrics -d risk_metrics -W
```

Команда предполагает, что имя пользователя и базы в `.env` — `risk_metrics`.
Пароль берётся из `.env` и вводится по запросу.

Для выхода из клиента: `\q`.

### Логи и остановка

Посмотреть последние сообщения:

```bash
docker compose logs --tail=50 db
```

Остановить и удалить контейнер, сохранив данные:

```bash
docker compose down
```

Данные PostgreSQL хранятся в именованном volume.
Команда `docker compose down -v` удаляет этот volume вместе с данными.

## Общие правила Git

`.gitignore` исключает локальные `.env`, зависимости, сборки, кэши, отчёты
проверок и настройки JetBrains / VS Code. Шаблоны `.env.example` и
`.env.*.example` остаются доступными для добавления в Git.

Исходники, миграции, Dockerfile, Compose, настройки инструментов проекта
и lock-файлы зависимостей необходимо хранить в репозитории.

## CI

Workflow `.github/workflows/ci.yml` запускается при push в ветку и при
создании или обновлении Pull Request. Он проверяет изменённые строки и
Compose, поднимает PostgreSQL 18.6, записывает контрольную строку и проверяет
её сохранность после пересоздания контейнера.

База CI создаётся на отдельной машине GitHub с тестовыми настройками.
В конце проверки контейнер и его volume удаляются. Локальная база
разработчика не используется. Доступ к Cbonds / RuData и тестовый сервер
для этой проверки не требуются.

Тесты и сборка backend/frontend будут подключены после появления каркасов
компонентов. Задача #18 остаётся открытой до проверки всего заявленного
объёма. Workflow зеркалирования GitLab выполняет отдельную задачу.
