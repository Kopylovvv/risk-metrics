# Методическая часть защиты (DV01)

Задача #16. Шпаргалка к показу: формула, каждый вход, контрольный пример, данные,
открытые вопросы. Подробности: `docs/control-example.md`, `docs/market-data-map.md`,
`docs/acceptance-sprint2.md`.

## 1. Что считаем

**DV01** — изменение стоимости позиции при росте доходности на 1 базисный пункт (0.01 %).
Показывает, сколько рублей позиция потеряет или заработает при сдвиге ставок.

```
DV01 = CFV × (−D × 1bp + ½ × C × 1bp²),  1bp = 0.0001
```

Это разложение Тейлора цены облигации по доходности: первое слагаемое — линейная
чувствительность (дюрация), второе — поправка на кривизну (выпуклость). При 1 bp
второе слагаемое на 4–5 порядков меньше первого.

## 2. Каждый вход формулы

| Вход | Смысл | Откуда | Единицы |
|---|---|---|---|
| CFV | текущая справедливая стоимость гипотетической позиции | считаем: количество × (номинал × цена% / 100 + НКД) × курс | рубли |
| количество | число бумаг в сделке, < 0 — шорт | вводит пользователь | штуки (у евробондов — лоты) |
| номинал | номинал одной бумаги | источник (Cbonds `nominal_price`) | валюта бумаги |
| цена% | чистая цена | источник (`indicative_price`) | % от номинала |
| НКД | накопленный купонный доход на бумагу | источник (`aci` или `get_aci`) | валюта бумаги |
| курс | валюта бумаги → рубль; для RUB = 1 | источник курсов (решается) | руб. за единицу |
| D | модифицированная дюрация | источник (`dur_mod`) | годы |
| C | выпуклость | источник (`convexity`) | годы² |

**Решения куратора (24.10.2026):**
- CFV по «грязной» цене (котировка с НКД), методика `dv01-v2`.
- В расчёте может быть несколько облигаций: DV01 по каждой строке и итог как алгебраическая сумма.

**Решения команды (сверх ТЗ):**
- Всё в рублях, чтобы суммировать сделки в разных валютах.
- Плавающий купон (правило ТЗ): D = 1 / число выплат в год, C = 0 — цена флоатера
  чувствительна к ставке только до ближайшего пересмотра купона.
- Без округления; округляет только интерфейс при выводе.
- Итог по набору = Σ DV01, только если посчитаны все сделки; иначе итога нет (`partial`),
  чтобы не показывать неполную сумму как полную.

**Знак:** лонг при росте ставок дешевеет → DV01 < 0; шорт → DV01 > 0.

## 3. Как проверяем результат

1. Контрольный пример считается вручную, арифметика записана рядом с тестом.
2. Ядро — чистая функция без сети и БД (`app/risk_core`), 26 тестов, в том числе проверка,
   что оно ничего, кроме арифметики, не импортирует.
3. Сквозной тест: ответ источника в формате Cbonds → адаптер → API → расчёт → БД
   (итог 209.464523609375).
4. Приёмка через живой API (`scripts/acceptance.py`): 14 проверок, все совпали.
5. Старый расчёт не меняется после правки сделок: в строке хранится копия всех входов.

Пример для слайда (fixed, 100 бумаг): CFV = 100 × (1000 × 95 % + 12.5) = 96 250 ₽;
DV01 = 96 250 × (−3 × 0.0001 + ½ × 12 × 0.0001²) = **−28.87 ₽** — при росте ставок на
1 bp позиция теряет ≈ 29 рублей.

## 4. Данные и доступы (по факту)

- Cbonds: адаптер по официальной спецификации; публичный демо-доступ отвечает, формат
  полей сверен (дюрация в годах, выпуклость ~ годы²), но полный снимок по одной бумаге
  в демо недоступен → нужен ключ.
- Курсы: предложен ЦБ РФ (бесплатно, официально), ждём решения.
- RuData: доступа нет.
- Нет данных → ошибка строки (`MISSING_MARKET_DATA` и др.), никогда не 0.
