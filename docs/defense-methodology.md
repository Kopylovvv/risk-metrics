# Методическая часть защиты (DV01)

Задача #16. Шпаргалка к показу: формула, каждый вход, контрольный пример, данные,
открытые вопросы. Подробности: `docs/control-example.md`, `docs/market-data-map.md`,
`docs/acceptance-sprint2.md`.

## 1. Что считаем

**DV01** — изменение стоимости позиции при росте доходности на 1 базисный пункт (0.01 %).
Показывает, сколько рублей позиция потеряет или заработает при сдвиге ставок.

```
DV01 = CFV × (−D × 1bp + ½ × C × 1bp²),  1bp = 0.0001
```

Это разложение Тейлора цены облигации по доходности: первое слагаемое — линейная
чувствительность (дюрация), второе — поправка на кривизну (выпуклость). При 1 bp
второе слагаемое на 4–5 порядков меньше первого.

## 2. Каждый вход формулы

| Вход | Смысл | Откуда | Единицы |
|---|---|---|---|
| CFV | текущая справедливая стоимость гипотетической позиции | считаем: количество × (номинал × цена% / 100 + НКД) × курс | рубли |
| количество | число бумаг в сделке, < 0 шорт | вводит пользователь | штуки |
| номинал | непогашенный номинал одной бумаги | Мосбиржа, `FACEVALUE` из итогов торгов | валюта номинала (`FACEUNIT`) |
| цена% | чистая цена закрытия | Мосбиржа, `LEGALCLOSEPRICE` | % от номинала |
| НКД | накопленный купонный доход на бумагу на дату торгов | Мосбиржа, `ACCINT` режима в валюте номинала | валюта номинала |
| курс | валюта номинала → рубль; для RUB = 1 | ЦБ РФ, `XML_daily.asp`: `Value` / `Nominal` | руб. за единицу |
| D | модифицированная дюрация | считаем по графику выплат биржи при её доходности, сверяем с `DURATION` | годы |
| C | выпуклость | считаем по тому же графику | годы² |

**Решения куратора (24.10.2026):**
- CFV по «грязной» цене (котировка с НКД), методика `dv01-v2`.
- В расчёте может быть несколько облигаций: DV01 по каждой строке и итог как алгебраическая сумма.

**Решения команды (сверх ТЗ):**
- Всё в рублях, чтобы суммировать сделки в разных валютах.
- Плавающий купон (правило ТЗ): D = 1 / число выплат в год, C = 0 — цена флоатера
  чувствительна к ставке только до ближайшего пересмотра купона.
- Без округления; округляет только интерфейс при выводе.
- Итог по набору = Σ DV01, только если посчитаны все сделки; иначе итога нет (`partial`),
  чтобы не показывать неполную сумму как полную.

**Знак:** лонг при росте ставок дешевеет → DV01 < 0; шорт → DV01 > 0.

## 3. Как проверяем результат

1. Учебный пример считается вручную, арифметика записана рядом с тестом.
2. Ядро: чистая функция без сети и БД (`app/risk_core`), в том числе проверка, что оно
   ничего, кроме арифметики, не импортирует.
3. Контрольный набор на реальных параметрах: записанные ответы Мосбиржи и ЦБ от 15.11.2026
   → адаптеры → API → расчёт → БД. ОФЗ 26238 +100: DV01 −31.56 ₽; ГазКЗ-34Д −10 (USD):
   +415.05 ₽; итог 383.48 ₽. Ожидаемые числа посчитаны отдельно и сверены с биржей
   (`docs/control-example.md`, раздел 3).
4. Дюрация по графику выплат совпадает с биржевой (2447.2 против 2447 дней, 2038.7 против
   2038): значит, потоки и доходность взяты верно, и выпуклость по тем же потокам надёжна.
5. Старый расчёт не меняется после правки сделок: в строке хранится копия всех входов.

Пример для слайда (fixed, 100 бумаг): CFV = 100 × (1000 × 95 % + 12.5) = 96 250 ₽;
DV01 = 96 250 × (−3 × 0.0001 + ½ × 12 × 0.0001²) = **−28.87 ₽** — при росте ставок на
1 bp позиция теряет ≈ 29 рублей.

## 4. Данные и доступы (по факту, 15.11.2026)

- Решение команды от 14.11.2026: облигации с Мосбиржи (ISS, публичный, без ключа), курсы
  валют с ЦБ РФ (официальные, бесплатно). Cbonds и RuData выведены из рабочего сценария.
- В ISS нет модифицированной дюрации и выпуклости: есть дюрация Маколея в днях и
  доходность. D и C считаем по графику купонов и погашений. Биржа дисконтирует ОФЗ по 365
  дням, часть валютных выпусков по 360; база определяется по цене, иначе D у валютной
  бумаги была бы на 1.4% меньше.
- НКД берём из режима торгов в валюте номинала: у долларовой бумаги в рублёвом режиме
  биржа отдаёт НКД, уже пересчитанный в рубли.
- Нет данных → ошибка строки (`MISSING_MARKET_DATA` и др.), никогда не 0.
- Карта полей и ограничения: `docs/market-data-map.md`.
