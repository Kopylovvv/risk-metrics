## 2. Актуальная инструкция пользователя

### 2.1. Доступ к стенду
* **Основной адрес:** https://teahorses.mhimf.net/
* Доступ осуществляется по защищённому протоколу HTTPS. Регистрация не требуется — сессия заводится автоматически при входе.

### 2.2. Порядок работы
1. **Добавление сделок в портфель:**
   * Введите 12 символов ISIN в левом верхнем поле (например, нажмите «Вставить пример (ОФЗ)» для `RU000A1038V6` или введите `RU000A105A95`).
   * В правом верхнем блоке отобразятся справочные данные выпуска (эмитент, тип купона, номинал, валюта расчётов, источник данных).
   * Введите количество бумаг (целое число). Для длинной позиции (покупка) введите положительное число, для короткой позиции (шорт) — отрицательное со знаком минус (например, `-10`).
   * Нажмите «Добавить сделку в портфель». Позиция появится в списке ниже.
2. **Управление составом портфеля:**
   * Для выбора сделки кликните по её строке: справочные параметры отобразятся в блоке справа.
   * Для изменения количества нажмите на иконку карандаша, введите новое число и нажмите клавишу `Enter` или иконку галочки.
   * Для удаления сделки нажмите на иконку корзины.
3. **Расчёт риск-метрики:**
   * Нажмите синюю кнопку «Запустить расчёт риск-метрики».
   * После окончания расчёта в правой панели отобразится статус («Полный расчёт»), суммарный риск DV01 в рублях (со знаком) и справедливая стоимость позиции (CFV).
   * В таблице детальных результатов по каждой бумаге указаны: применённый НКД с валютой, CFV в рублях, DV01 в рублях, источник котировки и дата, а также курс ЦБ РФ для валютных инструментов.
4. **Актуализация при изменениях:**
   * Если после расчёта вы изменили или удалили сделку, интерфейс покажет предупреждение: «Результат устарел». Нажмите «Запустить расчёт риск-метрики» для получения обновлённых значений.

## 4. Браузерное E2E тестирование (Задача #60)

Автоматизированный Playwright-сценарий расположен в `frontend/tests/e2e/portfolio.spec.ts`.

### 4.1. Состав автоматизированных проверок
1. **Инициализация сессии:** открытие `/`, проверка пустого состояния портфеля и неактивности кнопки расчёта.
2. **Добавление сделок:** лонг ОФЗ 26238 (`RU000A1038V6`, +100 шт.) и шорт ГазКЗ-34Д (`RU000A105A95`, −20 шт., подсветка красным).
3. **Редактирование по месту (In-place edit):** изменение количества бумаги со 100 на 150 с проверкой сохранения.
4. **Удаление сделки:** удаление ГазКЗ-34Д, проверка пересчёта количества позиций.
5. **Запуск расчёта (Full Success):** получение статуса «Полный расчёт», отображение `#total-dv01`, суммарного CFV и строк таблицы.
6. **Контроль устаревания (`isStale`):** добавление новой сделки после расчёта немедленно вызывает появление `#stale-badge` («Результат устарел») и предупреждающего блока `#portfolio-stale-warning`.
7. **Частичный расчёт (`partial`) без ложного итога:** добавление сделки без дюрации (`RU000A0JX0J2`), запуск расчёта. Проверка:
   * статус переходит в «Частичный расчёт»;
   * блок `#total-dv01` **скрыт**, выводится плашка «Итог не рассчитан: по части сделок нет результата»;
   * суммарный блок CFV **скрыт**;
   * сбойная строка содержит статус «Нет данных».
8. **Восстановление после F5:** вызов `page.reload()` и проверка полного восстановления набора сделок и статуса последнего расчёта (`last_calculation_id`).

### 4.2. Как запустить тесты

* **Локальный запуск против стенда или dev-сервера:**
  ```bash
  cd frontend
  npm run test:e2e                              # по умолчанию BASE_URL=http://127.0.0.1:8080
  # или против HTTPS стенда:
  BASE_URL=https://teahorses.mhimf.net npm run test:e2e
  ```
* **Запуск полного стека в изолированном Docker Compose с демо-данными:**
  ```bash
  python scripts/check_compose.py --e2e
  ```
  Скрипт разворачивает временный изолированный проект на свободных портах, накатывает миграции, наполняет базу контролируемыми тестовыми данными (`python -m app.stubs.demo_data`), запускает Chromium в headless-режиме, прогоняет сценарий и удаляет временные ресурсы.
* **Запуск в CI:**
  Подключён в `.github/workflows/compose.yml`. Выполняется на каждом push и PR в GitHub Actions.
