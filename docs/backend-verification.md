### Два независимых посетителя

| Действие посетителя B над набором A | Ответ |
|---|---|
| чтение набора, добавление, изменение, удаление сделки, расчёт | 404 `WORKSPACE_NOT_FOUND` |
| чтение расчёта A и `source-diff` | 404 `CALCULATION_NOT_FOUND` |
| CSRF-токен A с cookie B | 403 `CSRF_TOKEN_INVALID` |
| запрос без cookie | 401 `SESSION_REQUIRED` |

B видит только свой пустой набор и меняет только его; revision, сделки и расчёт A после
этого прежние.

### Revision и история

* Со старым revision изменение, добавление, удаление и расчёт дают 409
  `REVISION_CONFLICT`, набор не меняется.
* После правки количества 100 → 200 и новой загрузки на следующий день (цена 96%) старый
  расчёт отдаёт прежний ответ байт в байт: количество 100, цена 95, дата 13.11.2026.
  `source-diff` показывает отличие только в `price_pct`.
* Удаление сделки обнуляет `trade_id` в строке истории, значения остаются.
* UPDATE сохранённых снимков, курсов и результатов БД запрещает (миграция 0005).

### Обновление приложения

Сценарий из `docs/deployment.md` («Обновление проверенной версии»), без Docker:

1. Версия `main` `fe80ff5` (схема 0003, демо-данные) запущена, скрипт
   `python scripts/upgrade_check.py before` создал два набора (A: 100 и −10 бумаг, B: −5)
   и расчёты: A 357.670324218750, B 1.4434612500.
2. Остановка, `alembic upgrade head` новой версии (0003 → 0004 → 0005), запуск.
3. `python scripts/upgrade_check.py after` с теми же cookie:

```
  [OK] A: тот же набор 1e667c41, revision 2
  [OK] A: сделки [('RU000A1038V6', 100), ('XS0191754729', -10)]
  [OK] A: CSRF-токен прежний
  [OK] A: старый расчёт success 357.670324218750, прежние поля строк те же
      новые поля строки: ['currency', 'fx_rate_date', 'fx_source', 'settlement_currency']
  [OK] A: старый revision после обновления → 409
  [OK] A: новый расчёт success 357.670324218750
  [OK] A: чужой набор B → 404
  [OK] B: ... (те же проверки)
Итог: всё совпало
```

Тот же сценарий закреплён в CI тестом `test_stand_data_survives_upgrade_to_head`: данные
схемы 0003 (снимки `test` и `cbonds`, курс `demo`, расчёт) после `upgrade head` читаются с
прежними входами, новый расчёт берёт Мосбиржу и ЦБ, снимок Cbonds не используется.

Для стенда: перед обновлением `before`, после `docker compose up --build -d --wait`
скрипт `after` (файл с cookie лежит во временной папке, удалить после проверки).
