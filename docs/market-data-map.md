# Карта данных: Мосбиржа (ISS) и ЦБ РФ

Задачи #14, #66, #65, #68. Какие поля нужны расчёту DV01, откуда они берутся, в каких
единицах, какие ограничения и что делается, если поля нет. Решение команды от 14.11.2026:
параметры облигаций берём с Мосбиржи, курсы валют с ЦБ РФ; Cbonds и RuData выведены из
рабочего сценария (старые снимки остаются в БД только для истории расчётов).

Код: `backend/app/market_data/moex.py`, `cbr.py`, `bond_math.py`; контракт:
`MarketSnapshot` и `FxRate` в `backend/app/contracts.py`. Поля и формат сверены с
официальным описанием полей ISS (`/iss/history/engines/stock/markets/bonds/securities/columns`,
`.../yields/columns`) и с живыми ответами 15.11.2026 по ОФЗ 26238, ГазКЗ-34Д и ОФЗ 29021.
Записи этих ответов: `backend/tests/fixtures/moex`, `backend/tests/fixtures/cbr`.

## Запросы

Все запросы публичные, без ключа и логина.

| # | Запрос | Зачем |
|---|---|---|
| 1 | `iss/securities.json?q=ISIN` | SECID (у ОФЗ он не равен ISIN: `SU26238RMFS4`), основной режим торгов, `group = stock_bonds` |
| 2 | `iss/securities/{SECID}.json`, блок `description` | валюта номинала, вид облигации, частота купона, название |
| 3 | `iss/history/engines/stock/markets/bonds/securities/{SECID}.json?from&till` | итоги торгов по режимам за 14 дней до даты оценки: цена, НКД, номинал, валюта расчётов |
| 4 | `iss/history/engines/stock/markets/bonds/yields/{SECID}.json?from&till` | доходность и дюрация за выбранную дату торгов (только fixed и zero) |
| 5 | `iss/statistics/engines/stock/markets/bonds/bondization/{SECID}.json` | график купонов и погашений номинала (только fixed и zero); постраничный, `start` |
| 6 | `www.cbr.ru/scripts/XML_daily.asp?date_req=ДД/ММ/ГГГГ` | официальные курсы ЦБ на дату |

Берутся **итоги торгового дня** (`history`), а не текущие котировки (`marketdata`): так
повторный запрос на ту же дату оценки даёт те же числа, и работают даты в прошлом.

## НКД и режимы торгов

Бумага торгуется в нескольких режимах (`BOARDID`), `ACCINT` в итогах дан в валюте расчётов
режима. У ГазКЗ-34Д (номинал 1000 USD) на 13.11.2026:

| Режим | `CURRENCYID` | `ACCINT` | `LEGALCLOSEPRICE`, % |
|---|---|---|---|
| TQCB (основной) | SUR | 297.8993 | 96.2999 |
| TQOD | USD | 3.59 | 96.2999 |

297.8993 = 3.59 × 82.9803 (курс ЦБ на 13.11), то есть в TQCB тот же НКД в рублях. Адаптер
берёт НКД из режима в валюте номинала (TQOD: 3.59 $) и сам его не пересчитывает: база
начисления у выпусков разная (у ОФЗ дни/период: 31.7 = 35.4 × 163/182; у замещающих 30/360:
3.59 = 1000 × 8.625% × 15/360). Цена в % от номинала одна во всех режимах, поэтому её
можно взять из любого режима за ту же дату.

## Дюрация и выпуклость

В ISS нет ни модифицированной дюрации, ни выпуклости (ни в одном запросе официального
списка `/iss/reference`). Есть `DURATION` (дюрация Маколея **в днях**) и `EFFECTIVEYIELD`
(эффективная доходность, %) в `history/.../yields`. Адаптер считает по графику выплат
(`bondization`): купоны и погашения номинала после даты расчётов (T+1, следующий будний день;
праздники не учитываются) до `YIELDDATE` (к погашению или к оферте; если к оферте, в её
дату выплачивается непогашенный номинал).

```
t = дней / B,  v = CF / (1 + y)^t,  P = Σ v
D_mod = Σ t·v / P / (1 + y)
C     = Σ t(t+1)·v / P / (1 + y)²
дюрация в днях Σ дней·v / P сверяется с DURATION
```

**База года B у биржи разная.** ОФЗ дисконтируются по 365 дням, часть валютных выпусков
по 360. Сверка на итогах 13.11.2026 (расчёты 16.11):

| | B = 365 | B = 360 | ISS |
|---|---|---|---|
| ОФЗ 26238: цена по потокам | **548.209** | 540.615 | 51.592% × 1000 + 32.29 = 548.21 |
| ОФЗ 26238: дюрация, дней | **2447.2** | 2426.4 | 2447 |
| ГазКЗ-34Д: цена по потокам | 974.283 | **967.512** | 96.32% × 1000 + 4.31 = 967.51 |
| ГазКЗ-34Д: дюрация, дней | 2041.4 | **2038.7** | 2038 |

Поэтому формула `D_mod = DURATION / 365 / (1 + y)` для ГазКЗ-34Д дала бы 5.104 вместо 5.174
(ошибка 1.4%). Адаптер выбирает базу, при которой цена по потокам ближе к грязной цене биржи
(`PRICE` + `ACCINT` на дату расчётов из `yields`), затем сверяет дюрацию с `DURATION`
(допуск 2 дня или 0.1%). Не совпала, у будущего купона нет суммы или графика нет:
`duration_mod` и `convexity` пустые, у fixed строка получает `MISSING_MARKET_DATA`, а не
выдуманное число.

Итог на 13.11.2026: ОФЗ 26238 D_mod 5.7684, C 58.553; ГазКЗ-34Д D_mod 5.1765, C 36.692.

## Ограничения

* Выпуски с неизвестной суммой будущих купонов («Фиксированный с неизвестными купонами»,
  около 330 строк в списке облигаций ISS на 15.11.2026): дюрации и выпуклости нет,
  строка с ошибкой
* Флоатеры: D и C не нужны (правило ТЗ: D = 1/частота, C = 0), запросы 4 и 5 не делаются
* Дата расчётов T+1 без календаря праздников: сдвиг на день меняет D на сотые доли процента
* `bondization` нет в официальном списке запросов ISS, хотя он отвечает; не ответил:
  `PROVIDER_UNAVAILABLE`, backend возьмёт последний сохранённый снимок, если он есть
* Итоги дня появляются в `history` после закрытия торгов: оценка «на сегодня» днём берёт
  итоги предыдущего дня, их дата видна в `data_as_of`
* Амортизируемые бумаги: номинал непогашенный на дату торгов (`FACEVALUE`), вопрос эксперту ниже

## Ошибки

| Код | Мосбиржа | ЦБ |
|---|---|---|
| `INSTRUMENT_NOT_FOUND` | ISIN не найден или это не облигация (`group` не `stock_bonds`) | |
| `MISSING_MARKET_DATA` | нет итогов торгов с ценой за 14 дней | |
| `INCOMPATIBLE_MARKET_DATA` | другой ISIN или SECID, дата позже даты оценки, валюта не ISO, номинал или цена ≤ 0, НКД < 0, не число, нет режима в валюте номинала, график не в валюте номинала | курс ≤ 0 или не число, код валюты не ISO, дата курса позже запрошенной |
| `PROVIDER_UNAVAILABLE` | сеть, таймаут, HTTP-ошибка, не JSON, нет нужного блока, строка длиннее `columns` | |
| `MISSING_FX_RATE` | | ЦБ ответил, валюты в списке нет (евро в 1998 году) |
| `FX_PROVIDER_UNAVAILABLE` | | сеть, таймаут, HTTP-ошибка, не XML, нет даты (`Error in parameters`) |

Нет значения у источника → `None`, никогда не 0. Числа из JSON сразу в `Decimal`
(`parse_float=Decimal`), курсы ЦБ из строки с запятой.

## Открытые вопросы эксперту (#15)
