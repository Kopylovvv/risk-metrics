# Frontend: приёмка, E2E и выступление

Исходные UI, ТЗ и Playwright-сценарий подготовлены Егором в PR#81. Интеграционное
ревью и исправления CI/ожидания/асинхронной карточки выполнены Александром с помощью
ИИ. Полный протокол стенда с SHA и реальными результатами: `sprint3-acceptance.md`.

## Разные виды проверок

- Рыночный HTTPS smoke — `python3 scripts/check_https.py https://teahorses.mhimf.net`.
  Он использует Мосбиржу и ЦБ; контрольная дата13.11 даёт383.4813548556457…RUB.
- Ручной браузерный прогон версии#80: добавление ОФЗ+100 и ГазКЗ-34Д−10, расчёт,
  редактирование, устаревание, удаление/повторное добавление и восстановление послеF5.
  Текущая дата18.11 дала379.5258RUB (котировки17.11, курс18.11). Снимок и журнал
  находятся в общем протоколе. UI выбирает текущую дату, отдельного поля даты нет.
- Автоматические Playwright-тесты работают на отдельном временном Compose-проекте
  с явно `EXTERNAL_SOURCES=off` и TEST/demo-данными. Они подтверждают поведение UI,
  а не живой доступ к источникам или рыночные числа13.11.

## Автоматические браузерные проверки

1. Пустое состояние и запрет расчёта без сделок.
2. Добавление лонга и шорта, редактирование и удаление.
3. Реальный API-запрос расчёта, заблокированные формы на время ожидания.
4. Полный результат, CFV и явный баннер TEST/DEMO.
5. Устаревание результата по revision после изменения набора.
6. Partial при отсутствии обязательных параметров: нет ложного DV01 и CFV-итога.
7. Восстановление набора и результата после перезагрузки.
8. Поздний ответ справочника не заполняет карточку после ввода ошибочного ISIN.

Запуск из корня репозитория:

```bash
cd frontend
npm ci
npx playwright install chromium
cd ..
python3 scripts/check_compose.py --e2e
```

Скрипт создаёт собственные БД/порты, наполняет демо-данными, запускает тесты и удаляет
свои ресурсы. Переменная `E2E_SEEDED_DEMO=1` устанавливается этим скриптом только
после наполнения временной БД. Конфигурация Playwright требует её, чтобы эти тесты
не выдавались за приёмку произвольного сервера с другими данными. Для рабочего
HTTPS-стенда используется отдельный рыночный smoke выше. В CI весь сценарий входит
в обязательную job Compose; результаты привязываются к проверенному SHA.

## Текст Егора для показа (около40секунд)

«Я отвечаю за интерфейс. Пользователь вводит ISIN и количество бумаг, может
редактировать и удалять позиции. Расчёт показывает DV01 и CFV в рублях, источники,
даты и применённый курс. Если данных не хватает, общего итога нет. После изменения
набора прежний результат отмечается устаревшим. TEST/demo явно отделены от рынка.
Основной сценарий проверяется в Playwright через настоящий API во временном
окружении; реальные Мосбиржу и ЦБ проверяем отдельно на HTTPS-стенде».
